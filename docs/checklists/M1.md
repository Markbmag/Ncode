# M1 · Query engine & SQL mode: manual checklist

M1 has no screens yet (the builder and the SQL editor are M2); everything is tried in the API
docs at http://localhost:8000/docs (click **Authorize** and paste a token from
`POST /api/auth/login`). Report anything that fails with the exact message.

## 0. Install

- [ ] `cd backend && pip install -r requirements-dev.txt` (new: `sqlglot` 30.x). On Python 3.14,
      tell me if the install fails.
- [ ] `pytest` → all pass (live tests skipped unless you set the URLs, see README → Tests).

## 1. Optional, best test: run the live tests against scratch databases

Use an **empty scratch database** on each server (the tests create and drop `q_*` tables):

- [ ] `NCODE_TEST_PG_URL=... NCODE_TEST_MYSQL_URL=... NCODE_TEST_MSSQL_URL=... pytest tests/test_query_live.py`
      → all pass. Note your server versions if anything fails.

## 2. Questions on your real databases (read-only)

For one table with a date column and one foreign key in each database (MES, LES ...):

- [ ] `POST /api/query/compile` with a question that joins two tables **without** `on`: the SQL
      shows the join through the foreign key.
- [ ] `POST /api/query` with `aggregations` (sum + count_distinct), `breakouts` (a date with
      `"bucket": "month"`, plus a text column), a filter and `"order": [{"ref": "<alias>", "dir": "desc"}]`:
      status `completed`, months look right, column types are `date` / `string` / `number`.
- [ ] Same with `"bucket": "week"`: every date is a Monday.
- [ ] A `contains` filter with `%` in the value matches the literal `%` only.
- [ ] Run the same question twice: the second has `"cached": true`; with `"refresh": true` it is `false`.
- [ ] A question with a typo in a column name answers **400** with "Unknown column ...".

## 3. SQL mode

- [ ] `POST /api/query/sql` with `SELECT ... ORDER BY ...` on SQL Server and on MySQL: rows in your order.
- [ ] `{"limit": 5}` on a big table → 5 rows and `"truncated": true`; the next query on the same
      database still returns more than 5 rows.
- [ ] `{{param}}`: `SELECT * FROM t WHERE code = {{code}}` with `"params": {"code": "..."}` works;
      without `params` → 400 "Give a value for {{code}}".
- [ ] Rejected with a clear message: `SELECT LOAD_FILE('/etc/passwd')`, `SELECT SLEEP(5)`,
      `DELETE FROM t`, `SELECT 1; SELECT 2`, `SELECT * FROM t FOR UPDATE`.
- [ ] Accepted: `SELECT REPLACE(name, 'a', 'b') FROM t`, a string containing the word `update`, a
      column named `set` (quoted for your database).
- [ ] As a non-admin: `SELECT * FROM information_schema.tables` → 400; as admin → works.
- [ ] A slow query (a big join without filters) with `"wait_ms": 0` → `running`; `DELETE
      /api/query/tasks/{id}` → it ends as `cancelled` within a few seconds, and the database
      shows no leftover running query.
- [ ] `python -m app.manage audit --limit 10` lists the runs (actions `query` and `sql`).

- [ ] Search, Browse and Export as in the M0 checklist, section 4 (quick pass).
