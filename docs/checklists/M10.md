# M10 · Stabilise: manual checklist

Install: no new Python packages. In `frontend`, `npm install` (adds the browser-test runner
`@playwright/test`, a development tool only). On start, the app database gets indexes (migration
0008) and switches to WAL mode, so `ncode.sqlite-wal` and `ncode.sqlite-shm` appear next to it. That
is normal; back them up with the database or use **Back up now**. **Back up `backend/data/ncode.sqlite`
first.** Then run `python -m app.manage check` (see 7.), `pytest`, `npm test`, `npm run lint` and
`npm run build`. CI also runs the browser tests (`npm run e2e`).

## 1. Row-level security and Stop (security fixes)

- [ ] A group with a row rule (Admin → People) and a member. An admin opens **Profile** and
      **X-ray** of that table, and a Combine question with that table. Then the member opens the same
      three within a minute. The member sees only their rows (before M10, the admin's cached result).
- [ ] Two people: one runs a long query, the other starts a profile and presses **Stop**. The first
      query finishes normally.

## 2. Values and search

- [ ] SQL on PostgreSQL: `SELECT 'NaN'::float8, 'infinity'::timestamp, '{"a":1}'::jsonb,
      12345678901234567890::numeric` shows empty, `infinity`, `{"a": 1}` and the exact number.
      Before M10, "server not reachable".
- [ ] MariaDB: `SELECT TIME '838:59:59'` shows `838:59:59`.
- [ ] On a SQLite database: search and Browse for a Russian name in lower case find it written with
      a capital letter.
- [ ] SQL with `'{{not_a_parameter}}'` inside quotes or a comment runs without asking for a value.

## 3. Uploads and exports

- [ ] Upload a CSV saved by Russian Excel (`;`, Windows-1251, decimal commas): the dialog says what
      it found, the text is readable and the numbers are numbers. You stay on Uploads, with a
      *Use in Combine* button.
- [ ] A CSV with a line break inside a quoted cell uploads.
- [ ] A broken file gives a sentence without server paths.
- [ ] CSV export of a cell starting with `=`, `+`, `-` or `@` opens in Excel as text, not a formula.
      Plain negative numbers stay numbers.
- [ ] The DataDesk import works from a folder whose name contains `#`.

## 4. Saved content

- [ ] Open the same dashboard in two browsers, change and save it in one, then save in the other.
      The other says *Someone else saved this meanwhile*. Both *Reload their version* and
      *Save mine anyway* work. The same for a question (rename, save) and a collection (rename).
- [ ] A dashboard whose question was deleted can be duplicated and saved; the card shows *deleted*.
- [ ] Creating or moving something into an archived collection is refused with *Restore it first*.
- [ ] As a normal user: the sidebar shows no SQLite file paths and no ".env" lock.

## 5. Errors and Russian messages

- [ ] A question on a column that was renamed in the database gives a sentence naming the column
      and what to do. *Details from the database* shows the original text.
- [ ] Wrong database password in Admin → Databases → Check connection gives a clear reason.
- [ ] In Russian: the same errors, and a validation error such as a too short password, come in
      Russian.
- [ ] Stop the backend while a page is open, then click around. The page says it cannot reach the
      server, with *Try again*. Start the backend and *Try again* loads the page.

## 6. Interface fixes

- [ ] Russian names for custom columns and result names (e.g. "Сумма с НДС") are accepted and appear
      in results and charts.
- [ ] A dashboard date range with both dates typed quickly keeps both.
- [ ] Russian UI at phone width: Library, the builder steps and Combine have no sideways scrolling or
      cut-off buttons.
- [ ] Subscriptions: without email set up, the drawer says so (admins get a link). *Daily* means
      every day. A new subscription keeps the dashboard's current filters.
- [ ] Dates in results and lists: 12 Oct 2026 in English, 12.10.2026 in Russian.

## 7. Admin and upgrades

- [ ] Admin → **Broken content**: rename a table or column used by a question (on a test database),
      then *Check again*. The question is listed with the reason and a link. A database that is
      switched off shows as *couldn't check*, not as broken.
- [ ] `python -m app.manage check` prints ✓ lines (database, settings, key, connections, backups,
      disk) and exit code 0. Stop a database server and it prints ✗ with the reason and exit code 1.
- [ ] Follow *Upgrading* in [docs/guide/install.md](../guide/install.md) once (Windows or Docker).
- [ ] Admin → System → **Back up now** and a restore test on a copy (as in M9) still work with the
      `-wal` file present.

## 8. No regressions

- [ ] Search, Browse and CSV export work as before.
- [ ] The M9 checklist items for people, groups, row rules and audit still pass.

## What I verified here

- Backend: 701 tests, including PostgreSQL 16, MariaDB 10.11 and SQL Server 2022 live.
- Frontend: 124 unit tests, lint and build.
- Browser: 12 tests at desktop and phone width (`npm run e2e`): sign-in, search, browse, every page,
  error states with *Try again*, Russian, building and saving a question, a dashboard filter, an edit
  conflict, row rules, a Windows-1251 upload.
- CI: green, including the new *Browser tests* job.
- Load: 50 people opening a 6-card dashboard at once (`backend/tests/load_dashboard.py`). Median
  6.0 s → 4.2 s after WAL mode, no errors. Memory after 50 parallel sign-ins went from 875 MB to
  172 MB after moving password hashing to its own threads.
- Not verified here: Windows itself (paths with drive letters, deleting open files) and your real
  databases.
