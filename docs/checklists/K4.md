# K4 · Kanban for daily use: manual checklist

Install: no new packages. On start the app database gets migration 0014 (private boards, how long
finished tasks stay). **Back up `backend/data/ncode.sqlite` first.** Rebuild the frontend. Then
`pytest`, `npm test`, `npm run lint`, `npm run build`, `npm run e2e`.

## 1. Finished tasks leave the board

- [ ] A board with tasks finished more than 14 days ago: they are not in *Done* any more; *Finished
      earlier: N tasks* at the bottom of *Done* lists them, with search; one opens and can be moved back.
- [ ] Board *More → Board name, colour, hide → Finished tasks stay on the board*: 7 / 14 / 30 days /
      always. *Always* shows them all again.

## 2. Private boards

- [ ] *New board → Who can see the board → Only its members*. The board shows *Members only* with a lock.
- [ ] Someone who is not a member does not see it in the list or in My tasks, and its address says
      the board is not found. An admin sees it. *Everyone in the company* in the settings opens it again.

## 3. Print and Excel

- [ ] Board *More → Print*: the print preview shows one table per stage with empty boxes, who, due
      (late in bold), steps; with a filter on, only those tasks and a note saying so.
- [ ] *More → Download as Excel*: opens in Excel with real dates, a filter on the header row, Russian
      headers in the Russian interface, typed names next to Ncode users.
- [ ] *My tasks → Print* and *Excel* do the same for your own tasks.

## 4. Timeline

- [ ] *Board · Calendar · Timeline* (*График* in Russian): bars from start to due, late ones red,
      finished ones grey, today's line; it opens with today near the left, also on a phone.
- [ ] Drag a bar: both dates move. Drag its right end: only the due date. *Undo* puts them back.
      A tap on a bar or a name opens the task.

## 5. Without a connection (phone, installed on the home screen, over HTTPS)

- [ ] Open a board and a task once. Airplane mode, close the app, open it again: the board and the task
      are there, with *No connection* at the top.
- [ ] Tick a step, write a comment, take a photo, move the task to *Done*: each shows at once (*Waiting
      to be sent*), the strip counts them. Adding a new task says it needs the connection.
- [ ] Close and open the app again, still offline: the waiting changes are still there.
- [ ] Airplane mode off: *Sent 4 changes made without a connection*; on a computer the board shows them.
- [ ] Sign out while changes wait: it asks first. After signing out, nothing of yours is left on the phone.

## What I verified here

- Backend: private boards hidden from non-members everywhere (list, board, task, file, history,
  finished list, My tasks, Excel), members and admins see them; finished tasks leaving the board and
  coming back; Excel content (headers in Russian, dates, late, names); migration 0014.
- Frontend: unit tests for the timeline (weeks, bars, dragging rules) and the print rows; browser tests
  for a members-only board, the settings, Print (the sheet in print mode) and Excel (a download), the
  timeline (drag a bar and its end, Undo, open), and working offline (a tick, a comment, a photo and a
  move waiting, a new task refused, all four sent after reconnecting).
- The built app with its service worker, offline: reloaded, it showed the board and the task kept on
  the device; a tick and a comment survived a second offline reload and reached the server.
- A printed board as a PDF (A4): one table per stage, readable in Russian.
- Not verified here: a real iPhone (Safari keeps IndexedDB for home-screen apps; a long unused app may
  have it cleared by iOS, then the boards come back on the next connection).
