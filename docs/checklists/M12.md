# M12 · Simple questions: manual checklist

Install: no new packages and no migration. On start the demo gets "Show values as" settings for its
foreign keys and a true **Scrap rate** metric; existing metrics are kept. **Back up
`backend/data/ncode.sqlite` first.** Then `pytest`, `npm test`, `npm run lint`, `npm run build`,
`npm run e2e`.

## 1. The "done when": 6 clicks

- [ ] As a new user on the Factory demo: menu *New question* → *Scrap records* → *Sum* → split by
      *Line* → *per week* → *Last quarter*. A line chart with one line per production line, captioned
      "Sum of Scrapped pieces per Line and per week · last quarter". Same in Russian.

## 2. Quick question and suggestions

- [ ] *New question* opens the one-screen quick question; the *Full editor* switch is remembered.
      *Open in full editor* carries everything over.
- [ ] After picking a table, 3–6 ready questions appear (e.g. count per month, top 10 by a number).
- [ ] *Top N by…* in the quick question and in the builder's Summarise step.
- [ ] The chart shows why it was chosen ("Line chart: one date and one number"); in *Customize*
      chart types that cannot show the result are greyed out with the reason.

## 3. Values and names

- [ ] A builder filter on *Line* or *Status* offers the column's values (search, several at once,
      recent values); ids show their names ("3 · Final assembly").
- [ ] Grouping downtime by *Line* shows line names, not numbers. Admin → Data model → a foreign key
      → *Show values as* changes or switches this off.
- [ ] Row rules still apply to the value lists (a restricted user only sees allowed values).

## 4. Dashboards

- [ ] Edit a dashboard → add a *Period* filter → it connects itself to the cards' date columns
      ("connected by itself to n of m"); cards it doesn't reach show *not filtered by Period*.
- [ ] A category filter offers the values from a list.

## 5. Ratio metrics and pivot

- [ ] Admin → Data model → metric *Scrap rate* (Divide one total by another): all scrapped pieces ÷
      all pieces, as a percent. On the demo dashboard, *Scrap rate per line* is correct per line.
- [ ] Create your own ratio metric with a condition on one side; the live example updates.
- [ ] A result with two dimensions → chart *Pivot table* → Rows / Columns / Values areas (drag or ⋯),
      totals on/off. Download → Excel keeps the pivot layout with totals.

## 6. Saved questions, undo, previews

- [ ] Opening a saved question shows the result full width; *Edit* opens the editor, *Done* returns
      (asks about unsaved changes). Viewers see *Duplicate to edit*.
- [ ] Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z (and the buttons) undo and redo builder and SQL draft changes.
- [ ] Changing the table, *Start over* and removing a step with content ask first, then offer Undo.
- [ ] The eye button on a builder step shows its first 10 rows.

## 7. Layout (done during M12, on request)

- [ ] On a short window (e.g. 1280×650) the database switcher and your account stay in view; the
      menu scrolls. Below 1200 px wide the menu turns narrow (icons), the ◧ button widens it.
- [ ] Scrollbars and opened drop-down lists use the theme's colours.
- [ ] *Customize* next to the chart type changes a chart's look; on a dashboard in edit mode the ⚙ on
      a chart card does it for that card only.

## What I verified here

- Backend 800 tests incl. live PostgreSQL 16, MariaDB 10.11, SQL Server 2022 (ratio division and
  name joins per dialect). Frontend 257 tests, lint, build. Browser 38 tests incl. the 6-click path in
  EN and RU, value pickers, pivot drag and drop, undo, saved-question view, short and narrow windows.
- Known limits: value lists are not offered on public links; a chart change made in view mode is not
  carried into Edit; suggestion titles can read "Total Total" when a column is called "Total".
