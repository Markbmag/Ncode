# M6 · Federated workspace & datasets: manual checklist

Install: `cd backend && pip install -r requirements.txt` (new: **duckdb 1.5.x** - wheels exist for
Python 3.14 on Windows; `openpyxl` moved from dev to runtime). Frontend: no new packages.
The app database gets one new table on start (**back up `backend/data/ncode.sqlite` first**);
uploaded files go to `backend/data/datasets/`. Then `pytest`, `npm test`, `npm run build`, `npm run lint`.

You need two databases with a common key (the roadmap's case: MES and LES with a VIN), a CSV or
Excel file with the same key, and for the permission part a second non-admin user.

## 1. "Done when": MES and LES joined on VIN, report, saved, on a dashboard

- [ ] **Combine** → **Add source** → *Table* (or *Saved question* / *SQL*) on MES → Add.
      The source row shows its columns after a moment.
- [ ] **Add source** → LES (e.g. *SQL*: `SELECT vin, … FROM …`) → Add. The Join block suggests
      *Use vin = vin* → click it. The result appears (Live preview).
- [ ] The badge next to *Match report* says how many keys have no match. Open **Match report**:
      "N % of MES keys have no match in LES (x of y)", the other direction, examples of unmatched
      VINs, and a warning if a VIN repeats (rows are then counted more than once).
- [ ] If VINs differ in case or have spaces: set *Compare* to *As text, ignore case* → the share drops.
- [ ] Summarise (e.g. *Count of rows* and *Number of distinct* LES vin, grouped by plant) → **Save**
      into a collection → reload the page: it opens in Combine and runs.
- [ ] Dashboards → add the question as a card; add a filter (e.g. *List of values* "Plant") and
      connect it to the card's **column** `plant` → the card filters. Reload: it still works.
- [ ] Library → the question shows as *multi-source*; Duplicate, Move, Archive work.

## 2. Uploads

- [ ] **Uploads** → *Upload a file* → a CSV with `;` and dates like `01.09.2026` → the list shows rows
      and columns; *Combine* opens it as the first source and the dates are dates (Summarise →
      group by month works).
- [ ] An `.xlsx` (first sheet, then another sheet by name); a column with numbers and text stays text.
- [ ] A file over the size limit / with too many rows is refused with a clear message; an `.xls`
      asks for `.xlsx`/`.csv`.
- [ ] A collection page lists its uploaded files; *Upload a file* there saves into it.
- [ ] Archive a file → Library → Archive → *Restore* / *Delete* (its copy in `data/datasets/` is removed).

## 3. More combining

- [ ] Three sources (two databases + a file); each join on its own key; *Another key column* for a
      two-column key.
- [ ] Join types: *Only rows with a match* (fewer rows, warning in the report), *Keep all rows on both sides*.
- [ ] **Write SQL instead**: `SELECT … FROM mes JOIN les ON …` runs; `SELECT * FROM read_csv('C:/x.csv')`,
      `SELECT * FROM some_real_table` and `DELETE FROM mes` are refused with a message.
- [ ] A source that returns more than 100,000 rows is marked *cut off* in the report.
- [ ] Parameters: a saved SQL question with `{{status}}` used as a source → the combined question
      shows a *Status* input and passes it on; a filter set to *ask for the value* adds another.

## 4. Permissions

- [ ] A user without access to LES: running the shared multi-source question says the LES source is
      unknown; a question source or a file that is not shared with them is "not found".
- [ ] Sharing the collection *Can view* lets them run it when they have access to every database.

## 5. DataDesk

- [ ] `python -m app.manage import-datadesk … --map …` on your real `app-data.sqlite`:
      multi-database reports become multi-source questions (FULL JOIN on the key columns);
      reports imported before M6 show as *upgraded*. Please send the report.

## 6. No regressions

- [ ] Search, Browse, Export (M0), builder and SQL editor (M2), charts (M3), library and sharing (M4),
      dashboards (M5).
