# M4 · Library: questions, collections, sharing, importer: manual checklist

Install: no new packages. Pull, then `cd backend && pytest` and `cd frontend && npm test && npm run build && npm run lint`.
The app database is upgraded automatically on start (new tables: collections, questions, permissions,
favorites). **Back up `backend/data/ncode.sqlite` first.**

You need two users for the sharing part, e.g. `python -m app.manage create-user tester` (not an admin).

## 1. "Done when": create / save / open / share round-trips

- [ ] New question: build "revenue by region" → **Save** → name it, keep *My collection* → the URL becomes
      `/questions/<id>` and the title shows the name and the path *Library › …'s collection*.
- [ ] Reload the page → the same question, chart and settings come back and the result runs.
- [ ] Change something (e.g. switch to Chart) → *edited* badge → **Save** → badge gone.
      ⋯ → *Discard changes* also works.
- [ ] SQL editor: a query → **Save** → reopen from the Library → the SQL, row limit and chart come back.
- [ ] ⋯ → *Save as new question*, *Duplicate*, *Rename / describe*, *Move* each do what they say.
- [ ] Library → Start: the star adds a question to *Favourites*; the search box finds it by name.

## 2. Collections and sharing (permission tests)

- [ ] Library → **+** → collection "Sales" → move a question into it (row ⋯ → Move).
- [ ] Sales → **Share** → add the tester with *Can view* → Save access.
- [ ] As the tester: Library shows *Sales* (with the people icon); the question opens with *view only*,
      runs, has no **Save** (only *Save as new…*, which saves into the tester's own collection).
- [ ] As the tester: the question in your *own* collection (admin's personal one) is not visible, and
      opening its URL says it could not be opened.
- [ ] Change the tester to *Can edit* → the tester can now save changes and move/archive questions
      in Sales, but has no **Share** button and cannot move or archive Sales itself.
- [ ] A sub-collection of Sales inherits the access ("from “Sales”" in its share dialog).
- [ ] Remove the tester from Sales → the tester no longer sees it.
- [ ] A user without access to a question's database (`python -m app.manage allow tester other`) can
      open a shared question but is told they cannot run it.

## 3. Parameters

- [ ] SQL: `SELECT * FROM <table> WHERE <number column> >= {{min_value}}` → an input appears; ⚙ →
      type *Number*, default 10 → Run uses the default; typing another value re-runs with it.
- [ ] SQL with a date: `... WHERE <date column> >= {{since}}` with type *Date* → date picker works.
- [ ] Builder: a filter row → sliders button (*Ask for the value*) → the row shows *asks “…”* and an
      input appears above the result. Empty = the filter is left out (all rows); a value filters.
- [ ] Save, then copy the URL after typing a value (it contains `?p.<name>=`) → open it in another
      tab → the same value is filled in.
- [ ] ⚙ → *Required* and no value → the result says "Give a value for …".

## 4. Archive

- [ ] ⋯ → *Archive* on a question → it disappears from the lists and appears in Library → Archive.
- [ ] *Restore* brings it back; archive it again → *Delete* → gone for good.
- [ ] Archive a collection (its ⋯ menu) → its questions disappear from search; restore it.

## 5. DataDesk importer

- [ ] `python -m app.manage import-datadesk <path>/app-data.sqlite --map <datadesk_db>=<ncode_key> --dry-run`
      prints the report and writes nothing. **Please send me the report (and, if anything is
      skipped as "not known" / "no reports table", the output of `.schema` for that file).**
- [ ] Without `--dry-run` (add `--report import.md` to keep the report): Library → *DataDesk import* →
      one collection per dashboard; open a few imported questions and compare with DataDesk.
- [ ] Run the import again → everything is *already imported*, nothing is duplicated.
- [ ] Imported multi-database reports open with the "runs once federation arrives (M6)" note.
